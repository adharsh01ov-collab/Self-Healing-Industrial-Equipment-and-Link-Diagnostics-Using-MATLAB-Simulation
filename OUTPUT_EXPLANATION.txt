(Date: 10 Oct 2026)
======================================================================
COMMAND WINDOW OUTPUT

     -> No fault detected. Correct, Station 1 had no fault.

  Station 2: Stuck-sensor flags 142 / Missing-measurement flags 0
     -> The detector flagged 142 samples as "stuck". The fault lasts
        about 150 samples (15 s), so it was caught for most of the
        interval. Flags start after a short delay because the
        detector needs a window of 10 samples.

  Station 3: Stuck-sensor flags 0 / Missing-measurement flags 51
     -> 51 missing readings detected. This matches the 51 packets
        lost in Step 1.

  "Detection simulation completed."
     -> The script finished without error.

HOW DETECTION WORKS
  - Stuck sensor: look at the last 10 readings; if the range
    (max - min) is below 0.03, flag "stuck".
  - Missing data: a reading that is invalid or not available is
    flagged "missing".

IMPORTANT NOTE
  The numbers are DETECTOR FLAGS, not a count of separate faults.
  Many consecutive flags belong to the same single fault. False
  alarm and missed-detection rates were not measured.

FIGURE: "Automatic Fault Detection"
  Shows the signals with detected fault regions highlighted.

MEANING OF "STATION-SECONDS"
  Downtime is added across stations. Two stations down for 1 second
  at the same time = 2 station-seconds. So it is not simply the
  elapsed clock time.

DOWNTIME REDUCTION
  100.2 - 50.2 = 50.0 station-seconds saved
  (50.0 / 100.2) x 100 = about 49.9 % reduction

FIGURE: "SHIELD-MATLAB: Integrated Factory Simulation"

  2. Adaptive Controller Response - mode over time.
     Blue = Station 2 (DEGRADED around 60 - 110 s).
     Orange = Station 3 (SAFE STOP around 160 - 210 s).

HOW TO INTERPRET THE RESULT
  The adaptive controller completed more products with less
  downtime in this run. BUT:
   - It is a single run (no statistical proof).
   - The baseline uses instantaneous latency only, while the
     adaptive controller uses moving averages AND packet loss, so
     the rules are not identical.
   - The model is simplified and not validated on real equipment.
  Treat the result as promising evidence inside the simulation, not
  proof of the same gain in a real factory.
